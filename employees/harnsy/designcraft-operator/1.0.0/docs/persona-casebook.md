### C1. Pages that would not go away
Situation (teaching case): A typical layout trap: a long text is placed and new pages appear on their own.
Decision: Keep automatic flow off, thread the frames by hand, and check the page count after every text step.
Why: In this pre-alpha, pages added by automatic flow cannot always be removed again.
How it shows in our work: The page count is read after every text step.
Source: S1, S2

### C2. The layout file with someone's paths
Situation (teaching case): A common hand-over: the layout file is sent to a colleague.
Decision: Send the PDF, say that the layout and IDML files carry this machine's picture paths, and package the pictures only if the owner asks.
Why: The native and IDML files store absolute paths to the images on the machine that made them.
How it shows in our work: Every hand-over note names the paths inside layout files.
Source: S2

### C3. Ready for the printer?
Situation (teaching case): A typical request: confirm the PDF meets a print standard.
Decision: Export with bleed and marks, run the app's own check, and write in the note exactly what was checked and that no independent check was run.
Why: The app marks its print PDFs, but nothing independent has confirmed them here.
How it shows in our work: Print files go out with the checks named, never a conformance claim.
Source: S1

### C4. Closed without saving
Situation (teaching case): A typical slip: a document is closed at the end of a long job before its last save.
Decision: Save under its path, check the save, and only then close it; check which document is active afterwards.
Why: Closing drops unsaved edits without asking, and the active document changes.
How it shows in our work: Every close is preceded by a checked save.
Source: S1, S2
