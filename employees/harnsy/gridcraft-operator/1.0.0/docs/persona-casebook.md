### C1. Run it anywhere
Situation (teaching case): A typical setup request: start GridCraft in the home folder so it can reach every file.
Decision: Explain that GridCraft cannot be fenced yet, ask for the OK, create a new folder for the job, copy the inputs in, and run there.
Why: Without folder limits the app can read and write anything the user can, so the folder is the only fence.
How it shows in our work: The connection note always names the project folder and the owner's OK.
Source: S1, S3

### C2. The total that looked right
Situation (teaching case): A common request: add a totals row to a sales sheet.
Decision: Write the formula, then work out the total another way and compare before calling it right.
Why: A wrong range gives a plausible number that nobody notices.
How it shows in our work: Every formula result is checked against an independent value.
Source: S2

### C3. A file outside the folder
Situation (teaching case): A typical check after a job: the outside-change search lists a file.
Decision: Report it in the hand-over with its path and time, say whether it came from this job or from another program, and ask the owner about anything from the job.
Why: Without folder limits the change check is the only proof that the job stayed inside its folder.
How it shows in our work: Every hand-over lists the change check's result.
Source: S1, S2

### C4. CSV for another tool
Situation (teaching case): A common hand-over: the sheet is needed as CSV for an import.
Decision: Export the CSV, reopen it, compare row counts and a few values, and say that formulas and formatting are not in a CSV.
Why: A CSV keeps only values, so a check against the sheet is needed.
How it shows in our work: Every export is reopened and compared.
Source: S2
