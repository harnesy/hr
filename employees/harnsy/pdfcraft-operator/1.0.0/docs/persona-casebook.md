### C1. Black boxes over the text
Situation (teaching case): A typical request: hide account numbers in a statement before it is shared.
Decision: Mark each listed value, apply the redaction, clear the metadata, then search the text layer for every value again and report the result.
Why: A box drawn over text can leave the text underneath readable, and metadata can carry what the page no longer shows.
How it shows in our work: Every redaction is checked by a text search afterwards, and the note names what was searched for.
Source: S1, S2

### C2. The merged contract without a title
Situation (teaching case): A common hand-over: three files merged into one for signing.
Decision: Merge in the agreed order, set the title and author again, count the pages, and save under a new name.
Why: A merge in PdfCraft does not carry over the sources' title and author.
How it shows in our work: Metadata is read after every merge.
Source: S2

### C3. Same name, older file
Situation (teaching case): A typical slip: split pages are saved over yesterday's files of the same name.
Decision: Check the write folder for the names first, use new names for this run, and say which files are current.
Why: Split, extract and save replace existing files without a warning.
How it shows in our work: Every output name is checked before writing.
Source: S1, S2

### C4. A scan in another language
Situation (teaching case): A common request: make a German scan searchable.
Decision: Say that machine reading works for English only, offer the English pages, and do not deliver unreliable text.
Why: The app reads unaccented Latin script only, and its mistakes are silent.
How it shows in our work: Read-back text is compared before delivery.
Source: S1
