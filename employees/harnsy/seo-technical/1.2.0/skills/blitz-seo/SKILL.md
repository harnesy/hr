# Blitz SEO: a 30-day sprint for one page

Search work often fails because it is spread across too many pages. A sprint does the opposite: one query that matters to revenue, one page, thirty days of concentrated work, everything logged. It is a way to set priorities, not a trick, and it promises no position.

**Route:** candidates → one query and its owning page → baseline → page fixes → internal links → drafts for links and sharing → daily log → result at day 30 → second reading three to four weeks later.
Before this skill: search console access the owner gave, the list of pages, and the owner's word on which queries bring revenue. After it: a sprint plan, changes as proposals or pull requests for review, a log and a result report.

## When to use

- A page sits in positions five to twenty for a query tied to signups or sales.
- A launch needs one page to be found.
- Pages with weaker content outrank ours for a query we should answer best.
- The owner feels SEO work is everywhere and nothing moves.

Not for a brand-new domain that search engines barely know, and not for a query with no revenue behind it. Say so and propose regular work instead.

## Inputs

- Search console data: queries, pages, positions, impressions, click rate, with the date range. Only with access the owner gave; without it, positions are «not verified».
- The owner's answer: which queries, if won, would bring buyers.
- The list of our pages and the query ownership map.
- What is available: who can edit pages, existing articles to link from, people the owner could honestly ask for a link.

## Rules

- **One query, one page.** Three queries at most, and only if one page can answer all three. Saying no to the rest is the method.
- **The owning page wins.** Check the ownership map first. If two of our pages split the query, merge them before the sprint starts; a redirect of a page with traffic or links needs the owner's OK.
- **A sprint is judged as a whole.** Normally one change is measured at a time. A sprint stacks changes on purpose, so no single change can be credited. Log every change with its date, record the baseline before day 1, read the result at day 30 and again three to four weeks later.
- **No promises.** No position, no traffic figure, no «page one by day X». Results depend on competition and on signals outside our control.
- **Links are earned.** No buying links, no exchanges, no networks of sites, no automated comments or profiles. The link work here is a list of pages that would honestly gain from citing ours and a draft for the owner to send.
- **Nothing is posted or sent by the agent.** Posts for forums and social networks and outreach messages are drafts for the owner, only where the page truly answers the question asked there, and within that community's rules.
- **No keyword stuffing.** The query in the title, the H1 and the first paragraph, once each, in natural words. Related terms only where they belong.
- **A year in the title only when the page was really updated** for that year.
- **Request indexing once, after a real change.** Repeating the request does nothing.
- **The agent proposes; people ship.** Page edits go to the page owner or engineering as exact changes or a pull request for review. Never merge or deploy.

## Steps

1. **List the candidates.** From search console data: queries with buying intent where a page of ours ranks five to twenty with real impressions. For each: position, impressions, click rate, the page, and the owner's view of its revenue value.

2. **Pick the target.** The test: losing this query to a competitor would hurt. Read the first results: if they are a different page type from ours (a tool, a comparison, a marketplace), our page type must change or the target is wrong. Write the choice and the reason in two lines.

3. **Record the baseline.** Position, impressions, clicks and click rate for the query and the page over the last 28 days, with the source; the number of internal links pointing to the page; its real-user speed if the data exists.

4. **Fix the page.** One list of changes for the page owner:
   - the answer to the query in the first screen;
   - the query in the title, H1, description and, for a new page only, the URL;
   - sections the first three results have and ours lacks, plus the one thing only we can show: own data, real screenshots, a worked example;
   - proof a visitor can check: named customers and quotes only if real and approved;
   - speed and mobile layout, from field data;
   - structured data only for what is visible.
   Use the title rules of the content strategist's seo-title-optimization skill if it is hired; hand content gaps to the content strategist.

5. **Send internal links to the page.** List our pages that mention the topic, strongest first. Propose a link from each with descriptive anchor text; a link from the home page or the main navigation if the page deserves that place. A few per day is enough.

6. **Prepare link drafts.** List outside pages that would be better with a link to ours: articles that cite an older source, resource lists in our field, partners and customers. For each, a short draft to a named person with the specific reason. The owner decides and sends.

7. **Prepare sharing drafts.** Where people ask the question our page answers, draft a reply that helps even without the link, and list it for the owner. Skip places that forbid self-promotion.

8. **Work the daily list for 30 days.**
   - one internal link proposal, until the list is done;
   - one on-page improvement from the comparison with the first three results;
   - one link or sharing draft for the owner;
   - the day's position for the query, from search console data, or «not verified»;
   - a line in the log.
   If the same fix failed twice, stop it and say what was tried.

9. **Report at day 30,** and again three to four weeks later: baseline against result, what was shipped, what the owner sent, what is still open. If nothing moved, say that the limit is likely intent or authority, and what would change it.

## Output

```markdown
# Sprint plan: [query] → [page]

Why this query: ...
Baseline ([date range], [source]): position, impressions, clicks, click rate, internal links
Page changes: [checklist for the page owner]
Internal links: [from → anchor]
Link drafts: [page, person, reason]
Sharing drafts: [place, question, draft]
Calendar: days 1 to 30 with the daily list filled in

## Log
| Date | Change | Who shipped it | Position | Notes |
| --- | --- | --- | --- | --- |
```

## Checks before hand-over

1. One query (three at most) and one owning page, with the ownership check written down.
2. The baseline has a date range and a source, or says «not verified».
3. No step buys, swaps or automates links; nothing was sent or posted by the agent.
4. Every claim on the page is real; a year in the title matches a real update.
5. Every change is in the log with its date.
6. The plan and the report contain no promised position or date.

## Hand-over

- **To the page owner:** the page changes and titles to approve.
- **To engineering:** exact markup, speed fixes and internal links, as a list or a pull request for review.
- **To the content strategist:** content gaps and sections to write.
- **To the owner:** link and sharing drafts to send or drop, and the result reports.

## How far proven

Not run live by us. This skill is adapted from its source and checked by review, not yet used by harnsy on a real page. The source reports one sprint of its author; we did not verify it and repeat no figures from it. Treat the first run as a trial and report what did not fit.
